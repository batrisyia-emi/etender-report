Frontend reporting module with mock data and backend seams

A Flutter module rendering four reports and two dashboards for the SESB
eTender system, split between Supplier View and SE View.

Everything is frontend: no network calls, all data mocked. The work of
connecting a backend is confined to two interfaces in lib/data/

  ReportRepository  four endpoints; the record classes' fromJson define
                    the JSON contract, exercised on every run because the
                    mock rows are parsed through them
  ReportActions     six methods behind every button that leaves the module
                    or calls a server; the default throws so an unwired
                    button says so rather than appearing to work

README.md explains the seams and lists known gaps. docs/api-contract.md
has the field tables, status vocabularies and the rules a server must
enforce, including that the supplier endpoint must be scoped server-side.

Sample data is anonymised: suppliers and staff are fictional, amounts and
dates are retained so every figure and funnel count is unchanged.

The test suite has never executed. Windows Smart App Control blocks the
unsigned flutter_tester.exe on the development machine, so CI runs it on
Linux instead. Expect the first run to surface real failures.
